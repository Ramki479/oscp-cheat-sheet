Writing, deleting or relaying is not — confirm it is authorised first. ## Pivoting variant — internal hosts only If the target is reachable only through a pivot, prepend proxychains4 and keep the rest unchanged: proxychains4 nxc smb -u -p --shares. smbclient and rpcclient also traverse a SOCKS proxy, but every file download goes through it — copy single files instead of mirroring. If SMB stalls through SOCKS, forward the port instead: ssh -L 4455::445 @, then smbclient -p 4455 -L //127.0.0.1/. ## A. Detect SMB ### Step 01 — Confirm SMB and grab the version Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nmap -sCV -p139,445 ``` Look for: microsoft-ds on 445, netbios-ssn on 139, and a VERSION string with the host/domain.
Decision: open → Step 02. 445 closed but 139 open → older stack; still worth enumerating.
Next: Step 02.
Common mistake: stopping at "445 open" without a version — the version decides whether SMBv1 or a known CVE is even relevant.
Evidence: the port table and version string. ### Step 02 — NSE SMB baseline Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nmap -p139,445 --script smb-os-discovery,smb-security-mode,smb2-security-mode,smb-enum-shares,smb-enum-users ``` Look for: hostname, domain, OS build, message_signing state, share list, account list.
Decision: shares listed → Step 05. signing: disabled → read section I before acting on it.
Next: Step 05 (null session).
Common mistake: smb-enum-users needs a null session; an empty result usually means null sessions are off, not that there are no users.
Evidence: the OS/domain block and the share list. ## B. Version, dialect and signing ### Step 03 — Read the dialect and signing requirements Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nmap -p445 --script smb2-security-mode,smb2-capabilities ``` Look for: SMB2/3 message signing enabled but not required vs required.
Decision: "enabled but not required" = signing is optional → relay is possible in principle. "required" → relay to this host will fail.
Next: section I.
Common mistake: equating "signing not required" with "relay will work". Feasibility still depends on a coerced authentication and on the relayed identity having access.
Evidence: the exact signing line — quote it in the report. ### Step 04 — Force a protocol version when negotiation fails Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash smbclient -L /// -N -m SMB3 smbclient -L /// -N --option='client min protocol=SMB2' ``` Look for: a share listing instead of protocol negotiation failed.
Decision: SMB1-only host → -m NT1 (lab only; SMB1 is a red flag worth reporting).
Next: Step 05.
Common mistake: assuming a negotiation failure means the host is unreachable — it usually means the dialect is mismatched.
Evidence: the dialect you had to force. ## C. Anonymous and guest access ### Step 05 — Null session share listing Priority: Core · Run on: Kali · Status: Syntax Checked ```bash smbclient -N -L /// ``` Look for: a Sharename Type Comment table including IPC$, C$, ADMIN$.
Decision: NT_STATUS_ACCESS_DENIED → null sessions are disabled: move to credentialed enumeration. Listing works → Step 06.
Next: Step 06 (permissions) then Step 07.
Common mistake: -L is the list flag and is case-sensitive; -l does not exist.
Evidence: the share table. ### Step 06 — Permission map as null/guest Priority: Core · Run on: Kali · Status: Syntax Checked ```bash smbmap -H -u '' -p '' smbmap -H -u guest -p '' ``` Look for: a Disk/Permissions table with READ ONLY, READ, WRITE, or NO ACCESS.
Decision: any READ → Step 08. READ, WRITE → note it; uploading is a separate, authorised decision.
Next: Step 08.
Common mistake: empty -u '' is a null attempt, not a guest login — try both. NO ACCESS on C$ for a low-priv account is normal.
Evidence: the per-share permission table. ### Step 07 — NetExec null/guest pass Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash nxc smb -u '' -p '' --shares ``` Look for: SMB banner with host/domain, then share lines with READ/WRITE.
Decision: [+] with guest → same path as Step 06. STATUS_ACCESS_DENIED → no anonymous access.
Next: Step 12 once you have credentials.
Common mistake: NetExec is noisy in logs; it is fine in a lab, but it is not a stealth tool.
Evidence: the banner is a quick source of hostname/domain strings. ## D. Enumerate shares ### Step 08 — Recursive directory listing Priority: Core · Run on: Kali · Status: Syntax Checked ```bash smbmap -H -u -p -r --dir-only ``` Look for: an indented tree — backup folders, IT, Finance, user home directories, *.bak, *.config, scripts.
Decision: a directory looks interesting → Step 09 to pull it, or Step 11 to grab one file.
Next: Step 09.
Common mistake: capital -R is not a valid smbmap flag. The recursive flag is lowercase -r. -R fails with unrecognized arguments: -R (verified with smbmap -h; some course material prints it in uppercase).
Evidence: the tree, saved with -g if you want a grep-able output file. ### Step 09 — List a specific subdirectory Priority: Core · Run on: Kali · Status: Syntax Checked ```bash smbmap -H -u -p -r '/' ``` Look for: file names, sizes, dates; recently modified files are usually the intended lead.
Decision: readable files → Step 10 or 11. NO ACCESS on a subdirectory → try the parent or another account.
Next: Step 10 (bulk) or Step 11 (single file).
Common mistake: quoting the path — spaces in share or directory names break the argument without single quotes.
Evidence: the listing with timestamps. ## E. Access and explore shares ### Step 10 — Interactive smbclient session Priority: Core · Run on: Kali · Status: Syntax Checked ```bash smbclient -N /// smbclient -U '/%' /// ``` Look for: smb: \> prompt, or NT_STATUS_ACCESS_DENIED / NT_STATUS_BAD_NETWORK_NAME.
Decision: prompt appears → ls, cd, recurse ON, prompt OFF, mget *. Access denied → wrong account or wrong share name (case-insensitive but must exist).
Next: Step 11.
Common mistake: using //\ — smbclient wants forward slashes in the UNC path.
Evidence: a transcript of the listing you relied on. ### Step 11 — Non-interactive bulk download Priority: Core · Run on: Kali · Status: Syntax Checked ```bash mkdir -p && cd smbclient -N /// -c 'recurse ON; prompt OFF; mget *' ``` Look for: getting file \path\file lines, then files on disk.
Decision: transfer errors on long paths → download subdirectories one at a time with cd/mget.
Next: Step 13 (inspect locally).
Common mistake: running it from your home directory — you lose track of which box the files came from. Run inside .
Evidence: the mirrored tree itself. ### Step 12 — Download one specific file Priority: Core · Run on: Kali · Status: Syntax Checked ```bash smbmap -H -u -p --download '//' smbclient -U '/%' /// -c 'get ' ``` Look for: the file appearing locally at the target path, or a file not found error.
Decision: success → Step 13. Failure on a path that was listed → quote the path exactly; spaces need quoting.
Next: Step 13.
Common mistake: downloading to a name that already exists — you silently overwrite earlier evidence.
Evidence: the file plus its source path. ### Step 13 — Inspect what you pulled Priority: Core · Run on: Kali · Status: Syntax Checked ```bash find -type f -exec file {} + grep -RIn -E 'pass|pwd|secret|token|key|connectionString' ``` Look for: config files, .kdbx, .pfx, scripts with hardcoded credentials, database backups, unattend.xml, .ssh directories.
Decision: credentials found → validate them carefully (Step 14) and record where they came from. Nothing found → continue enumeration; not every share is the path.
Next: Step 14.
Common mistake: grepping only for "password" — also try pw, sa, uid=, user id=, and base64-looking strings.
Evidence: the file path plus the exact line containing the credential. ## F. Authenticated enumeration ### Step 14 — Validate credentials and enumerate the domain in one pass Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nxc smb -u -p -d --shares --users --groups --loggedon-users --pass-pol ``` Look for: [+] auth success, share permissions, user list with badpwdcount, group memberships, active sessions, lockout policy.
Decision: (Pwn3d!) → local admin, move to secrets dumping (Advanced). Valid but no admin → harvest more shares and BloodHound data.
Next: Step 15.
Common mistake: running --users before reading --pass-pol — you may be two attempts from locking out every account.
Evidence: the auth line (host + domain + user), the share table, the policy. ### Step 15 — Re-enumerate every share with the new identity Priority: Core · Run on: Kali · Status: Syntax Checked ```bash smbmap -H -u -p -d ``` Look for: shares that were NO ACCESS before and are now readable — this is the single most common "new credential" win.
Decision: new access → back to Step 09/11 with that share.
Next: Step 09.
Common mistake: assuming your first enumeration was complete. Permissions are per-account; every new credential means re-running the basics.
Evidence: the before/after permission difference. ### Step 16 — RPC enumeration Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash rpcclient -U "" -N -c "enumdomusers;enumdomgroups;querydominfo" rpcclient -U '/%' -c "enumdomusers" ``` Look for: user:[name] rid:[0x...], group lists, domain info.
Decision: users found → build a username list (never brute force before reading the password policy).
Next: password policy, then careful spraying.
Common mistake: RID cycling (impacket-lookupsid) is noisy and often unnecessary once you have one credential.
Evidence: the user/group list with RIDs. ## G. Investigate findings ### Step 17 — Follow usernames Priority: Core · Run on: Kali · Status: Documented - Collect every sAMAccountName into . - Check the password policy before any spraying (--pass-pol). - Reuse found credentials across SMB, WinRM, RDP and MSSQL — one password often opens two services. - A username with no password is still useful: it feeds Kerberos user enumeration and AS-REP roasting. ### Step 18 — Follow files and backups Priority: Core · Run on: Kali · Status: Documented - *.bak, *.old, *.zip, *.7z, *.vhd, *.kdbx → extract and grep. - PowerShell scripts and .bat files often contain service-account credentials. - web.config/appsettings.json → connection strings with SQL credentials. - unattend.xml, sysprep.inf → local admin passwords (sometimes base64). ### Step 19 — Follow configuration and scripts Priority: Conditional · Run on: Kali · Status: Documented - A script that maps a drive or calls net use reveals credentials and share names. - A scheduled task definition reveals a service account. - Note the file path: it is evidence and often the answer to "where did this credential come from?". ## H. Signing, relay feasibility and prerequisites ### Step 20 — Build a relay candidate list Priority: Advanced · Run on: Kali · Status: Syntax Checked ```bash nxc smb /24 --gen-relay-list ``` Look for: hosts where signing is not required, one IP per line.
Decision: domain controllers never appear (they require signing). A non-empty list is a candidate list, nothing more.
Next: only with explicit authorisation: Responder + ntlmrelayx.
Common mistake: treating this output as proof of exploitability. Relay needs (1) a host that does not require signing, (2) a coerced or captured authentication, (3) an identity with access to the target.
Evidence: the candidate list plus the signing evidence from Step 03. ### Step 21 — SMBv1 / MS17-010 check Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash nmap -p445 --script smb-vuln-ms17-010 ``` Look for: VULNERABLE with the CVE-2017-0143 family.
Decision: vulnerable → confirm patch level and prerequisites before any attempt; this exploit can crash the host.
Next: validate in a snapshot if the exam allows it.
Common mistake: running EternalBlue against a fragile exam VM and losing the box.
Evidence: the script output, and the OS build that supports the claim. ## I. Troubleshooting | Error | Meaning | Fix | | --- | --- | --- | | NT_STATUS_LOGON_FAILURE | Bad credentials, or wrong domain | Check -d ; try --local-auth in NetExec | | NT_STATUS_ACCESS_DENIED | Authenticated but no rights to that share | Try another share or account; check smbmap permissions | | NT_STATUS_BAD_NETWORK_NAME | Share name does not exist | Re-list shares; watch spaces and $ suffixes | | NT_STATUS_IO_TIMEOUT | 445 filtered | Try 139 (-p 139), or confirm the host is up | | protocol negotiation failed | Dialect mismatch | -m SMB2 / -m SMB3 / -m NT1 | | session setup failed: NT_STATUS_MORE_PROCESSING_REQUIRED | Kerberos clock skew or unsupported auth | Sync time (sudo ntpdate / timedatectl), or use NTLM | | smbclient: command not found | Package missing | sudo apt install smbclient smbmap | | Works with IP, fails with hostname | Name resolution | Add the entry to /etc/hosts | Stop condition: if null, guest and one credential all fail and the share list is empty, SMB is probably not the entry point — move to another service and come back only with a new credential. ## J. Quick workflow 1. nmap -sCV -p139,445 — confirm and version. 2. NSE baseline (Step 02) — OS, domain, shares, users. 3. smbclient -N -L /// — null session. 4. smbmap -H -u '' -p '' — permissions. 5. smbmap -r --dir-only — map the tree (lowercase -r). 6. Download and inspect (Steps 11-13). 7. With credentials: nxc smb ... --shares --users --groups --pass-pol. 8. Re-run Steps 5-6 with the new identity. 9. Record signing status and whether relay is actually feasible. ## K.
