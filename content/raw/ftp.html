Status: Lab Tested = executed against an authorised lab target · Simulated = exercised with simulated output or fixtures · Syntax Checked = flags checked against the installed tool here · Environment Dependent = needs a specific tool, version or host configuration · Documented = standard technique, not run here. ## Prerequisites and execution location - Runs on: Kali Linux. - Needs: ftp or lftp; wget/curl; nmap. - Protocol distinction — do not mix these up: - FTP — port 21 control, plaintext, separate data connection (active/passive). - FTPS — FTP over TLS; still port 21 with AUTH TLS, or implicit on 990. - SFTP — SSH subsystem on port 22. It is not FTP and none of the FTP commands below apply. Use [SSH — Complete Command Reference](https://app.notion.com/p/4011e51238b58123b446cc627bc02913). ## Pivoting variant — internal hosts only proxychains4 ftp -p carries the control channel, but FTP needs a second data connection, which SOCKS handles badly. Prefer an explicit forward: ssh -L 2121::21 @, then ftp -p 127.0.0.1 2121 (passive). If active mode is required, the forward must be reversed — ssh -R — because the target connects back to you. ## 1. Detect FTP ### Step 01 — Confirm the service and version Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nmap -sCV -p21 ``` Look for: 21/tcp open ftp plus product/version, and whether ftp-syst/ftp-anon ran as part of -sC.
Decision: open → Step 02. Version like vsftpd 3.0.3 is common and not automatically vulnerable.
Next: Step 02.
Common mistake: assuming the banner version is exploitable — check the distribution's patches first.
Evidence: the banner and version. ### Step 02 — FTP NSE checks Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nmap -p21 --script ftp-anon,ftp-syst,ftp-vsftpd-backdoor ``` ```bash # manual anonymous check — 230 = granted, 530 = denied, no 230/530 line = read the full trace curl -sS --max-time 10 -v ftp://anonymous:anonymous@/ 2>&1 | grep -E '^< (220|230|530)' ```
Result What it means Next action
Anonymous FTP login allowed Anonymous access confirmed Step 03 for the banner, then Step 04 to list files
Anonymous FTP login denied, or the manual check prints 530 Anonymous access is really refused Stop anonymous attempts — go to Step 06 with credentials
No ftp-anon line, and the manual check prints no 230/530 Inconclusive: the scanner gave you nothing either way Investigate the trace (timeout, TLS-only, proxy); only a refused login closes this path
Look for: Anonymous FTP login allowed, ftp-syst server type/features, backdoor response.
Failure path: no ftp-anon line at all does not prove anonymous is off. The script prints nothing on some servers and builds — during this site's audit a local pyftpdlib server granted anonymous login while ftp-anon returned nothing. Treat an empty result as inconclusive, run the manual check above, and only then decide.
Decision: read the result three ways (table above). Anonymous FTP login allowed → Step 03, then log in at Step 04. Backdoor positive → Step 09 (validate first; most 2.3.4 builds are clean). Neither line printed → manual check, then Step 03/04 or Step 06.
Next: Step 03 when anonymous works, Step 06 when it is denied.
Common mistake: ftp-bounce is obsolete on modern servers, and an empty script result is not a negative — confirm it by hand before you write the service off.
Evidence: the anonymous result and the manual check that confirmed it — it is usually the whole path. ## 2. Enumerate the daemon ### Step 03 — Read the banner directly Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nc -nv 21 ``` Look for: 220 (vsFTPd 3.0.3) or similar; sometimes a hostname or internal domain.
Decision: banner reveals a hostname → add it to /etc/hosts and check DNS/vhosts.
Next: Step 04.
Common mistake: leaving the connection open — type QUIT or Ctrl-C.
Evidence: the banner line, especially any hostname. ## 3. Anonymous access ### Step 04 — Try the anonymous account Priority: Core · Run on: Kali · Status: Syntax Checked ```bash ftp -p ``` Look for: 230 Login successful (or 230 Anonymous access granted).
Decision: success → Step 06. 530 → anonymous disabled, move on unless you have credentials.
Next: Step 06.
Common mistake: -p means passive mode, not "port". The login is anonymous with any password (conventionally an email).
Evidence: the login response and directory listing. ### Step 05 — Anonymous access with lftp Priority: Conditional · Run on: Kali · Status: Environment Dependent ```bash lftp -u anonymous,anonymous ``` Prerequisites: lftp is an optional extra (sudo apt install lftp) and is not installed on the build host used for this audit — that is why this step is Environment Dependent. Step 04 (ftp) and Step 07 (wget) do the same job with tools that ship by default.
Look for: lftp :~> prompt.
Decision: works → ls, then mirror (Step 07). Fails or the command is missing → fall back to ftp or wget.
Next: Step 07.
Common mistake: lftp is not always installed (sudo apt install lftp); it is optional.
Evidence: same as Step 04. ## 4. Log in and list ### Step 06 — List and navigate Priority: Core · Run on: Kali · Status: Syntax Checked ```bash ftp -p # at the ftp> prompt ls -la binary ``` Look for: directories named backup, public, upload, www, conf; dotfiles; *.zip, *.sql, *.bak.
Decision: www or public_html present → the FTP root may be web-served: check [HTTP & HTTPS — Complete Command Reference](https://app.notion.com/p/4011e51238b581649211c0c5db9c94f8) on 80/443.
Next: Step 07.
Common mistake: forgetting binary before downloading archives — ASCII mode corrupts zips and binaries.
Evidence: the recursive listing. ## 5. Download and mirror ### Step 07 — Mirror everything Priority: Core · Run on: Kali · Status: Syntax Checked ```bash mkdir -p && cd wget -m ftp://anonymous:anonymous@/ ``` Look for: a mirrored tree and a transfer log ending without errors.
Decision: passive mode fails (425) → add --no-passive-ftp (forces active; only if your host is reachable from the target). Credentials → ftp://:@/.
Next: Step 09.
Common mistake: credentials in the URL end up in shell history and process listings — acceptable in a lab, not in real engagements.
Evidence: the mirrored files with timestamps. ### Step 08 — Single file over an interactive session Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash ftp -p # at the ftp> prompt binary get ``` Look for: 226 Transfer complete.
Decision: 550 Failed to open file → wrong path or no read permission.
Next: Step 09.
Common mistake: get file without an output path writes to the current directory and can overwrite evidence.
Evidence: the file and the exact command. ## 6. Inspect what you pulled ### Step 09 — Triage the contents Priority: Core · Run on: Kali · Status: Syntax Checked ```bash find . -type f -exec file {} + grep -RIn -E 'pass|pwd|secret|token|key|user' . ``` Look for: config files, SQL dumps, SSH keys, scripts with credentials, .bash_history, *.bak.
Decision: credentials → validate elsewhere (SSH/SMB/HTTP). Source code → look for upload endpoints and hardcoded paths.
Next: Step 10, or the service the credentials belong to.
Common mistake: only reading filenames — the interesting data is usually inside .conf, .env, *.sql, *.php.
Evidence: file path plus the line containing the finding. ## 7. Version and configuration investigation ### Step 10 — Check the version against known issues Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash searchsploit vsftpd 3.0.3 searchsploit proftpd ``` Look for: matching exploits and their required conditions.
Decision: candidate found → read it fully and confirm the exact build before running anything.
Next: Step 11 only with authorisation.
Common mistake: the vsftpd 2.3.4 backdoor (CVE-2011-2523) only affects the specific trojanised source release — most distributions shipped a clean 2.3.4.
Evidence: the version string plus the exploit's prerequisites. ## 8. Write access (conditional) ### Step 11 — Test write permission with a harmless file Priority: Advanced · Run on: Kali (against an authorised lab target) · Status: Documented ```bash echo test > /tmp/test.txt ftp -p # at the ftp> prompt put /tmp/test.txt ``` Look for: 226 Transfer complete, or 550 Permission denied.
Decision: writable and the directory maps to a web root → an upload path may exist; confirm the web path before uploading anything else. Writable but not web-served → limited value.
Next: [HTTP & HTTPS — Complete Command Reference](https://app.notion.com/p/4011e51238b581649211c0c5db9c94f8) if web-served.
Common mistake: overwriting or deleting existing files. Upload a new, uniquely named file and remove it afterwards.
Evidence: the upload confirmation and the resulting URL/path. ## 9. Authorised exploitation paths ### Step 12 — Prerequisites before attempting anything Priority: Advanced · Run on: Kali · Status: Documented - Backdoored vsftpd 2.3.4 — only the trojanised release; trigger opens a shell on 6200. Confirm the build first; this is not a generic 2.3.4 exploit. - Anonymous write + web root — upload a webshell only if the FTP directory is served by HTTP and the extension is executable. - Weak credentials — after reading any policy; FTP has no lockout by default, but brute force is slow and noisy. - ProFTPD mod_copy — SITE CPFR/SITE CPTO can copy files without auth on misconfigured servers (version-dependent). > Every item above is a lab technique. None of them is a first step, and each needs its precondition verified first. ## 10. Troubleshooting | Symptom | Cause | Fix | | --- | --- | --- | | 530 Login incorrect | Bad credentials, or anonymous disabled | Try anonymous/any password; verify the username | | 530 Permission denied after login | Account lacks FTP rights | Try another account | | 425 Failed to establish connection | Passive data port blocked | passive / -p on, or --no-passive-ftp in wget as a last resort | | Connection hangs after 230 | Data channel blocked | Switch passive/active mode | | 550 Failed to open file | Path or permission | ls the exact directory first | | AUTH TLS refused | Plain FTP only | Use ftp, not FTPS | | SSL_connect: wrong version | FTPS server with a legacy TLS version | openssl s_client -connect :21 -starttls ftp to inspect | Stop condition: anonymous denied, no credentials, and no writable or web-served directory → FTP is a dead end. Move to the next service. ## 11. Quick workflow 1. nmap -sCV -p21 — version. 2. nmap --script ftp-anon,ftp-syst,ftp-vsftpd-backdoor -p21 — anonymous check. 3. ftp -p — log in as anonymous, ls -la. 4. wget -m ftp://anonymous:anonymous@/ — mirror. 5. file + grep the loot — credentials, configs, source. 6. searchsploit — only if the version is unusual. 7. Write test — only if authorised and the directory looks web-served. 8. Record the banner, the anonymous result, and every file path you used. ## 12.
