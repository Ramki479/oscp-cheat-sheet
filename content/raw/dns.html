Status: Lab Tested = executed against an authorised lab target · Simulated = exercised with simulated output or fixtures · Syntax Checked = flags checked against the installed tool here · Environment Dependent = needs a specific tool, version or host configuration · Documented = standard technique, not run here. ## Prerequisites and execution location - Runs on: Kali Linux. - Needs: dig (bind9-dnsutils), dnsenum, dnsrecon; a wordlist for bruteforce. - Always query the target's resolver with @. Without it you are asking your own DNS and learning nothing about the target. ## Pivoting variant — internal hosts only SOCKS carries TCP only, so force TCP: proxychains4 dig +tcp @ . A plain UDP dig through proxychains will simply time out. Zone transfers are already TCP, so proxychains4 dig axfr @ works unchanged. ## 1. Detect DNS ### Step 01 — Confirm DNS is listening Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nmap -sCV -p53 sudo nmap -sU -p53 --script dns-nsid ``` Look for: domain on 53/tcp, and a BIND/NSID response on UDP.
Decision: TCP 53 open is required for zone transfers; UDP is enough for ordinary queries.
Next: Step 02.
Common mistake: concluding "no DNS" from a UDP open|filtered result — confirm with dig.
Evidence: the version and whether TCP 53 is open. ## 2. Basic record lookups ### Step 02 — A and AAAA Priority: Core · Run on: Kali · Status: Syntax Checked ```bash dig @ A +short dig @ AAAA +short ``` Look for: one or more addresses. Empty output with NOERROR means the name exists but has no record of that type.
Decision: an internal IP resolves → add it to your target list and scan it.
Next: Step 03.
Common mistake: dropping @ and hitting your own resolver (or the internet).
Evidence: the resolved addresses. ### Step 03 — NS, MX, TXT, CNAME, SOA Priority: Core · Run on: Kali · Status: Syntax Checked ```bash dig @ NS +short dig @ MX +short dig @ TXT +short dig @ CNAME +short dig @ SOA +short ``` Look for: authoritative name servers, mail hosts, SPF/verification strings, the SOA's primary NS and admin mailbox.
Decision: NS names → resolve and test each for a zone transfer (Step 05). MX hosts → SMTP enumeration. SOA → the zone's primary server, often the DC.
Next: Step 04 (reverse) and Step 05 (transfer).
Common mistake: treating TXT as noise — SPF records leak internal hostnames and third-party services.
Evidence: the record set per type. ## 3. Reverse lookups ### Step 04 — PTR for one address Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash dig -x +short ``` Look for: a hostname, or nothing.
Decision: name returned → resolve it forward and check for sibling hosts. Empty → normal.
Next: Step 05.
Common mistake: expecting PTRs for private ranges unless the DNS server is authoritative for them (common in AD labs).
Evidence: the name, if any. ## 4. Zone transfer ### Step 05 — Attempt AXFR Priority: Core · Run on: Kali · Status: Syntax Checked ```bash dig axfr @ ``` Look for: a full record listing, or Transfer failed.
Decision: success → every hostname goes into /etc/hosts and gets probed (Step 07). Failure → normal, secure configuration; go to Step 06.
Next: Step 07 on success, Step 06 on failure.
Common mistake: trying only one server. Repeat the AXFR against each NS from Step 03 — one may allow it while another refuses.
Evidence: the full zone dump, saved to . ## 5. Subdomain enumeration ### Step 06 — dnsenum (records + bruteforce + AXFR) Priority: Core · Run on: Kali · Status: Syntax Checked ```bash dnsenum --dnsserver -f ``` Look for: host records, bruteforced names, and its own AXFR attempt.
Decision: new hostnames → resolve and probe them. Nothing → try Step 07 with a different wordlist.
Next: Step 07.
Common mistake: --dnsserver is mandatory for internal domains; without it dnsenum queries public DNS and returns nothing useful.
Evidence: the host list. ### Step 07 — dnsrecon (SRV + brute) Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash dnsrecon -d -n -t std dnsrecon -d -n -t brt -D ``` Look for: SRV records, A/NS/MX tables, bruteforced subdomains.
Decision: SRV records for _ldap._tcp / _kerberos._tcp → you have found a domain controller (Step 08).
Next: Step 08 or the web page.
Common mistake: -t std is passive-ish and fast; -t brt needs a wordlist and time — do not run it blind against a huge list.
Evidence: the SRV block. ## 6. Hostname handling ### Step 08 — Map names to IPs Priority: Core · Run on: Kali · Status: Syntax Checked ```bash echo " " | sudo tee -a /etc/hosts getent hosts ``` Look for: getent returning the target IP.
Decision: names resolve → browse by hostname and re-run vhost discovery.
Next: [HTTP & HTTPS — Complete Command Reference](https://app.notion.com/p/4011e51238b581649211c0c5db9c94f8).
Common mistake: overwriting /etc/hosts instead of appending, and adding names you have not confirmed.
Evidence: the /etc/hosts line. ## 7. Active Directory SRV records ### Step 09 — Find the DC through DNS Priority: Core (AD labs) · Run on: Kali · Status: Syntax Checked ```bash dig @ _ldap._tcp. SRV +short dig @ _kerberos._tcp. SRV +short dig @ _gc._tcp. SRV +short ``` Look for: 0 100 389 .. style answers.
Decision: a DC hostname appears → add it to /etc/hosts and start AD enumeration.
Next: Active Directory — Complete Command Reference (batch 3).
Common mistake: querying with the FQDN of the DC but not adding the record for itself — Kerberos needs both name forms.
Evidence: the SRV answers — they prove the domain name and the DC. ## 8. Troubleshooting | Symptom | Cause | Fix | | --- | --- | --- | | connection timed out; no servers could be reached | UDP 53 filtered | dig +tcp @ | | REFUSED | Recursion disabled for your source | Query the authoritative zone directly; try AXFR | | NXDOMAIN | Name does not exist | Correct name, or brute-force | | SERVFAIL | Broken zone or forwarding | Try another NS | | no servers could be reached on -x | Private range not in DNS | Normal; use forward records instead | | AXFR Transfer failed | Transfers restricted | Try each NS; otherwise brute-force | Stop condition: if A, NS and AXFR all fail, DNS is probably not the path. Move on and return only if a hostname appears elsewhere. ## 9. Quick workflow 1. nmap -sCV -p53 — confirm TCP/UDP DNS. 2. dig @ A/NS/MX/TXT — records. 3. dig axfr @ — transfers, then against each NS. 4. dnsenum --dnsserver -f — brute force. 5. Add names to /etc/hosts and probe them. 6. In AD: query the SRV records, then move to the AD page. ## 10.
