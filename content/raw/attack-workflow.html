> Purpose: one ordered route through this handbook — from "VPN up" to "report submitted" — with a time box and a single next action for every phase. ## How to use this page - Work top to bottom. Do not jump to exploitation before enumeration has produced a version, a credential or a reachable path. - Every phase names the page to open next. - Time boxes assume the 23h45m exam and 5 machines. Stretch them for practice; keep the order. ## Phase 0 — Setup (first 15 minutes)

```bash mkdir -p ~/exam/{recon,loot,notes,report} sudo openvpn .ovpn & sleep 5 ip a | grep -A1 tun0 ``` Decision: no tun0 → reconnect before doing anything else. A broken tunnel looks exactly like a dead host. ## Phase 1 — Enumeration (60-90 minutes per machine) 1. Is it up? ping -c 3 ; if silent, scan with -Pn anyway. 2. Full TCP range — not just the top 1,000: sudo nmap -p- --min-rate 5000 -T4 -oA /tcp_full . 3. Version + default scripts on the ports that answered: sudo nmap -sCV -p -oA /svc . 4. UDP when the host looks sparse or the services suggest it (SNMP, DNS, IPMI): sudo nmap -sU --top-ports 50 . 5. Route each service to its page:
Port Service Open
21 FTP
22 SSH
53 DNS
80, 443, 8000, 8080, 8443 HTTP/HTTPS
139, 445 SMB
anything else unknown script lookup, then the service's own client
Decision: full scan empty or only one odd port → re-scan with -T3 (packet loss causes false negatives), check UDP, then move on. Do not spend two hours on a host that has nothing. ## Phase 2 — Foothold Work in this order — each step is cheaper and more reliable than the next: 1. Known-vulnerable version → research the exact build, read the exploit, then run it. 2. Reuse found credentials across every service (SMB → WinRM → RDP → SSH → web login). This is the most common intended path. 3. Misconfiguration — anonymous FTP, null SMB session, writable share, open NFS, exposed Git or backup files. 4. Web application flaw — upload, traversal, IDOR, default login, exposed admin panel. 5. Brute force — last resort, and only after reading the password policy. Rules that save points: - Read every exploit before running it; note its prerequisites. - Capture the proof the moment you land — shells die, reverts happen. - Never leave a box in a broken state for a later objective. - Keep a revert log; you have 24 reverts, resettable once. ## Phase 3 — Local enumeration and privilege escalation

Full triage order and exploitation paths live on those two pages. This page only tells you when to go there: immediately after the first shell, not after you get stuck. ## Phase 4 — Active Directory set The AD set hands you a username and password — start from there, not from a port scan. 1. Enumerate the domain with the credential (users, groups, computers, sessions). 2. Kerberoast and AS-REP roast; crack offline. 3. Read the password policy before spraying. 4. Run BloodHound and read the shortest path. 5. Abuse ACLs, delegation or local admin → DCSync. 6. Prove admin on each of the three machines as you go. Full command reference: [Active Directory — Complete Command Reference](https://app.notion.com/p/4011e51238b58122ac9bc9c86520d03e) . ## Phase 5 — Proof capture The proof rules are strict and mechanical: ```bash # Linux cat /root/proof.txt; cat /home//local.txt ip addr # Windows type C:\Users\Administrator\Desktop\proof.txt ipconfig ``` - Read the file from its original location, in an interactive shell, with cat or type. - The screenshot must show the file contents and the target IP from ipconfig/ifconfig/ip addr. - Submit the contents in the control panel before the exam ends. - A web shell, or any other method of reading the file, scores zero for that machine. ## Phase 6 — Reporting 1. Export the report to PDF. 2. Name it OSCP-OS-XXXXX-Exam-Report.pdf. 3. Archive to .7z (no password), same base name. 4. Upload within 24 hours to [upload.offsec.com](http://upload.offsec.com) and verify the MD5 hash. Details and the full submission checklist: [OSCP Exam Checklist & Evidence Collection](https://app.notion.com/p/4011e51238b58192a726f4738738085a) . ## Time budget (23h45m total)

Situation Next action
No open ports Re-scan -T3 (loss), check UDP, confirm the IP, then move on
Ports, no credentials Version research, one default-credential attempt, read the web app
Credentials, no admin Re-enumerate shares with the new identity; run BloodHound; local privesc
Local privesc blocked Services, scheduled tasks, sudo -l, kernel, credentials on disk
Exploit fails twice Stop. Re-read the version and prerequisites; your target may be patched
90 minutes, no progress Revert, re-read the objectives, switch machine — come back fresh
## Common failure modes - Stopping at the top-1,000 port scan and missing the real service. - Not re-enumerating after every new credential. - Running an exploit without reading it, then losing the box. - Forgetting the proof screenshot with the IP visible. - Submitting proofs after the exam window closes. - Using a restricted tool (SQLmap, mass scanners, AI assistants) and losing the machine. ## Evidence discipline - Directory per machine: ~/exam/loot//. - File naming: ---.txt. - Paste the command and its output into the notes as you go — reconstructing it later is where points are lost. ## Related pages
