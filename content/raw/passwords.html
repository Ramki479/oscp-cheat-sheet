> Purpose: turn a captured hash into a usable credential — identify it, pick the right mode, crack it with the cheapest method that works, then reuse or spray it. Every mode below is the one you will actually meet on an exam box. ## Mode cheat sheet | Hash | Source | hashcat | John | | --- | --- | --- | --- | | NTLM | SAM, secretsdump, --ntds | -m 1000 | --format=NT | | NetNTLMv2 | Responder, SMB relay capture | -m 5600 | --format=netntlmv2 | | Kerberoast TGS (RC4) | GetUserSPNs -request | -m 13100 | --format=krb5tgs | | AS-REP (RC4) | GetNPUsers -no-pass | -m 18200 | --format=krb5asrep | | Linux shadow SHA-512 | /etc/shadow | -m 1800 | --format=sha512crypt | | Linux shadow MD5 | /etc/shadow | -m 500 | --format=md5crypt | | DCC2 | cached domain creds | -m 2100 | --format=mscash2 | | MD5 / SHA-1 | web apps, databases | -m 0 / -m 100 | --format=raw-md5 | Crack in this order: fast hashes (NTLM, NetNTLMv2) with a wordlist → same with rules → masks only if the pattern is known. Kerberoast TGS is slow; budget time for it. ## A. Identify and organise ### Step 01 — Identify the hash Priority: Core · Run on: Kali · Status: Syntax Checked ```bash hashid -m '' hashid -m '' | grep -i hashcat ``` Look for: the hashcat mode in the output ([+] Hashcat Mode: 1000).
Decision: multiple candidates → match the source (SAM dump = NTLM, Responder capture = NetNTLMv2). Never guess from length alone.
Next: the matching crack step.
Common mistake: putting a NetNTLMv2 capture into -m 1000. It will never crack — the formats are different.
Evidence: the hashid output and the source of the hash. ### Step 02 — Keep hashes in separate files Priority: Core · Run on: Kali · Status: Syntax Checked ```bash mkdir -p /hashes # one file per type: ntlm.txt, netntlmv2.txt, tgs.txt, asrep.txt, shadow.txt wc -l /hashes/*.txt ``` Look for: a count per file that matches what you captured.
Decision: mixed file → split it first. hashcat stops at the first malformed line in some modes.
Next: Step 03.
Common mistake: appending every dump into one file, then wondering why half the hashes "fail". Separate by mode.
Evidence: the file list with line counts. ## B. Crack the common types ### Step 03 — NTLM Priority: Core · Run on: Kali · Status: Syntax Checked ```bash hashcat -m 1000 # with the usual rockyou hashcat -m 1000 /usr/share/wordlists/rockyou.txt ``` Look for: Status……….Cracked and the plaintext in the potfile.
Decision: not cracked after the wordlist → Step 08 (rules), then a targeted mask if you know the policy.
Next: Step 10 (show) and reuse the password.
Common mistake: cracking NTLM when you can pass the hash instead. If the hash grants admin, cracking is optional.
Evidence: the cracked line and the host that produced the hash. ### Step 04 — NetNTLMv2 Priority: Core · Run on: Kali · Status: Syntax Checked ```bash hashcat -m 5600 ``` Look for: a cracked challenge/response line (USER::DOMAIN:challenge:response:blob).
Decision: weak password → credential reuse. Strong → relay instead of cracking (SMB page), or move on.
Next: validate the credential with nxc.
Common mistake: trying to pass a NetNTLMv2 hash. It is a challenge/response, not an NT hash — it cannot be used for pass-the-hash.
Evidence: the cracked credential and the capture source. ### Step 05 — Kerberoast TGS Priority: Core · Run on: Kali · Status: Syntax Checked ```bash hashcat -m 13100 ``` Look for: $krb5tgs$23$*… cracking to a service account password.
Decision: slow to crack → target accounts whose password policy is weak, or check if the account is in a path to DA first (BloodHound).
Next: authenticate as the service account.
Common mistake: cracking a TGS for an account that leads nowhere. Check the path before spending hour-long runs.
Evidence: the crack result and the SPN it belonged to. ### Step 06 — AS-REP Priority: Core · Run on: Kali · Status: Syntax Checked ```bash hashcat -m 18200 ``` Look for: $krb5asrep$23$… cracking quickly (AS-REP is usually faster than TGS).
Decision: cracked → log in without Kerberos pre-auth. Not cracked → the account may be low-value; move on.
Next: validate and enumerate as that user.
Common mistake: confusing AS-REP (18200) with TGS (13100). The prefixes $krb5asrep$ and $krb5tgs$ tell you which.
Evidence: the cracked password and the user. ### Step 07 — Linux shadow Priority: Core · Run on: Kali · Status: Syntax Checked ```bash hashcat -m 1800 # older MD5-crypt entries hashcat -m 500 ``` Look for: the username and plaintext after cracking.
Decision: readable /etc/shadow → crack offline; writable → replace root's hash instead (Linux PrivEsc page).
Next: su on the target.
Common mistake: cracking the whole shadow file including locked entries (!, *). Strip those lines first.
Evidence: the shadow line and the recovered password. ## C. Improve the attack ### Step 08 — Rules and masks Priority: Conditional · Run on: Kali · Status: Environment Dependent ```bash hashcat -m 1000 -r /usr/share/hashcat/rules/best64.rule hashcat -m 1000 -a 3 ?u?l?l?l?l?d?d?d ``` Prerequisites: hashcat is installed, but rule files ship separately in hashcat-data and the set varies by distribution. best64.rule is absent on the build host used for this audit (ls /usr/share/hashcat/rules to see yours) — install hashcat-data, add the missing rule file, or point -r at one that exists. The mask line needs no rule file. Look for: Cracked after the rules pass, where the plain wordlist failed.
Decision: rules fail → mask only if the policy implies a pattern (e.g. Summer2026!). Otherwise switch to another hash type.
Next: Step 10.
Common mistake: running a full ?a?a?a?a?a?a mask — it is effectively infinite. Bound the mask to what the password policy allows.
Evidence: the rule/mask that worked. ### Step 09 — John the Ripper Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash john --wordlist= john --wordlist= --format=NT john --show ``` Look for: John auto-detecting the format and printing ().
Decision: hashcat has no mode for an exotic format → try John, which supports more formats out of the box.
Next: reuse the credential.
Common mistake: letting John auto-detect a shadow file with mixed formats; specify --format= explicitly.
Evidence: the john --show output. ### Step 10 — Show and reuse what you cracked Priority: Core · Run on: Kali · Status: Syntax Checked ```bash hashcat -m 1000 --show hashcat -m 1000 --show --outfile john --show ``` Look for: hash:plaintext pairs.
Decision: a password works locally → check sudo -l/su; works on the domain → spray it (Step 11) and use it for lateral movement.
Next: Step 11 or the target's privesc page.
Common mistake: forgetting --show and re-cracking hashes already in the potfile. Check the potfile before starting a long run.
Evidence: the --show output, saved to . ## D. Use a password without cracking ### Step 11 — Password spraying with NetExec Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nxc smb -u -p '' --continue-on-success ``` Look for: a small number of [+] successes across the user list.
Decision: hit → validate and enumerate. Zero → stop after one round; do not iterate variations.
Next: enumerate as the successful user.
Common mistake: spraying without checking the domain policy (lockout threshold). One password, one attempt per user, then wait.
Evidence: the successful logins and the policy that made the spray safe. ### Step 12 — Hydra SMB brute force Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash hydra -L -P smb:// # single user, password list hydra -l -P smb:// ``` Look for: [445][smb] host: … login: … password: ….
Decision: a hit → validate with nxc. Hydra's SMB module is slow and unreliable against modern Windows — prefer nxc smb -u user -p pass loops for a handful of candidates.
Next: reuse the credential.
Common mistake: running a full brute force against a domain account. Lockout will end the engagement — spray, do not brute force.
Evidence: the successful login line. ## E. Decision tree | What you have | Do this | Do not | | --- | --- | --- | | Unidentified hash | hashid -m • check the source (Step 01) | Guess the mode from length | | NTLM and admin access | Pass the hash (Post-Exploitation) | Spend an hour cracking | | NetNTLMv2 | -m 5600 (Step 04) | Try pass-the-hash with it | | Kerberoast TGS | -m 13100, after checking the path (Step 05) | Crack every SPN you see | | AS-REP | -m 18200 (Step 06) | Confuse it with TGS | | Shadow readable | -m 1800/500 (Step 07) | Crack locked entries | | Wordlist fails | Rules (Step 08) | Infinite masks | | Cracked a domain password | Spray once (Step 11) | Brute force (Step 12) | | Nothing cracks | Relay, reuse elsewhere, or move on | Keep the GPU busy for hours | ## F. Troubleshooting | Symptom | Cause | Fix | | --- | --- | --- | | hashcat No hashes loaded | Wrong mode / bad line endings | file, dos2unix, correct -m | | Exhausted immediately | Empty wordlist / wrong path | Check wc -l on the wordlist | | Cracks nothing on a known-good hash | Mode mismatch | Re-check with hashid -m | | Very slow | Kerberos/shadow mode | Expected; use rules before masks | | Token length exception | Line contains extra fields | Strip to the hash only | | John skips entries | Mixed formats | --format= per file | Pivoting variant. Cracking is local — no target connectivity needed. Spraying and validation are not: through a pivot, use proxychains4 nxc smb … and keep concurrency low, or you will trip account lockout and proxy timeouts at the same time. ## G.
