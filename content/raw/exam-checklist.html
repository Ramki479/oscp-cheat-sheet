> Purpose: a tick-list for the 24 hours before the exam, the first 30 minutes, every machine, every proof, and the submission window. If a box is unticked, do not move on. ## T-7 days - ☐ Re-read the current official exam guide; note its date. - ☐ Confirm tool restrictions (SQLmap, mass scanners, AI chatbots) and Metasploit limits. - ☐ Check Kali is updated: sudo apt update && sudo apt full-upgrade. - ☐ Confirm your wordlists exist: ls /usr/share/seclists/Discovery/Web-Content/. - ☐ Test the report template: one dummy machine, one PDF export, one .7z. - ☐ Practise the proof screenshot: cat + ip addr in the same terminal, one image. - ☐ Confirm your note-taking page structure (Machine Notes template). ## T-24 hours - ☐ Sleep. A 23h45m exam is an endurance event. - ☐ Prepare food, water, coffee, and a second internet connection if possible. - ☐ Charge laptop, test webcam/microphone for proctoring. - ☐ Clean the desktop; close anything you do not want a proctor to see. - ☐ Create ~/exam/{recon,loot,notes,report}. - ☐ Confirm the VPN client works with a practice .ovpn if you have one. ## First 30 minutes - ☐ Start the proctoring session and authenticate. - ☐ Download and extract the exam connection pack. - ☐ Connect: sudo openvpn .ovpn; confirm tun0 with ip a. - ☐ Note the exact start time; compute the hard stop (23:45 later). - ☐ Open the control panel; read every machine's specific objectives. - ☐ Create one notes page per machine from the template. - ☐ Confirm target IPs and put them in the notes. - ☐ Do not start scanning before the notes exist. ## Per machine - ☐ Record name, IP, OS, points, objectives. - ☐ Full TCP scan (-p-) with -oA into . - ☐ Version + default scripts on open ports. - ☐ UDP top-50 if the host looks sparse. - ☐ Service-specific enumeration from the matching handbook page. - ☐ Credentials table: username, secret, source path, where validated. - ☐ After every new credential, re-enumerate SMB shares, WinRM, RDP, SSH and web logins. - ☐ Local enumeration immediately after the first shell. - ☐ Privesc attempt documented with the command that proved it. - ☐ Revert log updated if you revert. - ☐ Dead ends recorded (they explain your time). ## Per proof - ☐ local.txt read with cat/type from its original path. - ☐ proof.txt read the same way, as root/Administrator/SYSTEM. - ☐ Screenshot shows file contents + IP address (ip addr/ipconfig). - ☐ Shell is interactive — not a web shell, not a one-liner from a tool. - ☐ Contents pasted into the control panel before the exam ends. - ☐ Screenshot filename recorded in the notes next to the command. - ☐ Screenshot inserted into the report beside the step that produced it. ## Evidence conventions
Item Convention
Directory ~/exam/loot//
Scan output --.nmap/.xml
Screenshots --.png
Notes one page per machine, append-only
Credentials username · secret · type · exact source path · where validated
> The report must let a competent reader repeat your attack. If a command is not in the notes, it will not be in the report. ## Time checkpoints
Elapsed You should be here
0:15 VPN up, objectives read, notes created
4:00 First standalone owned, proof captured
8:00 Second standalone owned, or a clear blocker documented
12:00 Third standalone owned, or re-prioritised
17:00 AD set: all three machines owned
20:00 Report writing started
22:00 Report drafted; proofs re-checked
23:00 Submission package built and tested
23:45 Exam ends — no more submissions to the control panel
## Last 60 minutes of the exam - ☐ Every local.txt and proof.txt submitted in the control panel. - ☐ Every proof has a screenshot with the IP visible. - ☐ Report has one section per machine, in the order you want them graded. - ☐ Commands and outputs are present for each attack step. - ☐ Modified exploits include the diff explanation; unmodified ones include only the URL. - ☐ Report exported to PDF and archived to .7z without a password. - ☐ File name matches OSCP-OS-XXXXX-Exam-Report.7z. ## Submission (within 24 hours) ```bash 7z a OSCP-OS-XXXXX-Exam-Report.7z OSCP-OS-XXXXX-Exam-Report.pdf ls -lh OSCP-OS-XXXXX-Exam-Report.7z md5sum OSCP-OS-XXXXX-Exam-Report.7z ``` - ☐ Upload to [https://upload.offsec.com](https://upload.offsec.com) (under 200 MB). - ☐ Compare the MD5 shown by the site with your local md5sum. - ☐ Click Submit File. - ☐ Wait for the confirmation email (check spam). - ☐ Keep a local copy of the archive. ## If something goes wrong | Problem | Action | | --- | --- | | VPN will not connect | Reconnect; if it persists, report in the proctoring chat immediately | | Machine unresponsive | Revert once, wait, then report it | | Proctoring tool drops | Reconnect it first; contact support via live chat if it fails | | You lose a shell | Revert only if needed;
